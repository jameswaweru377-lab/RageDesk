# RageDesk 0.8 — Connected Deep Navy UI (Preview 4)

Download **RangeDesk-Setup-0.8.0-preview.4-win-x64.exe** below and double-click it; no PowerShell is required. The approved React + TypeScript + WebView2 deep-navy dashboard is now the primary RageDesk window. The original WPF backend retains the existing .NET 10 download engine and stays hidden after React loads, appearing when advanced native actions need it. Use the **RangeDesk Classic (WPF)** Start Menu shortcut for fallback.

## Connected features
- Direct HTTP(S) downloads: add/start/queue, real progress, resume, pause, stop, queue ordering, open file/folder, details and batch actions. Confirmed **Remove History** never deletes files or checkpoints.
- Schedule queued direct-file downloads (once/daily/weekdays/weekly) in local time with daylight-saving checks. The app must be running at the scheduled time.
- Locally saved Settings: dark/light theme, start-immediately preference, connections, simultaneous transfers, bandwidth and a Windows download-folder picker.
- Browser Capture: open Chrome extensions and the bundled extension folder, register the current-user native messaging host and check registration. Manually captured direct-file links are offered in the React review dialog. Chrome extension installation and permissions remain a manual opt-in, and auto-capture stays off until enabled in the browser.
- Bundled recognizable logos for selected installers, plus safe file-type fallbacks; no third-party image requests. The compiled HTML/CSS/JS frontend is in the installed `web/` directory.

## Standard installation directory
For a **new all-users installation**, setup prefers **C:\Program Files\RangeDesk** (x64 Windows; administrator approval required). For current-user installation it uses `AppData\Local\Programs\RangeDesk`. **Existing Preview 3 installations reuse their prior installation mode and directory** to avoid duplicate installations. To move an old per-user copy to Program Files, uninstall it first (data and downloads remain intact), then install Preview 4 selecting all users. Reconnect browser native messaging if the app directory changes.

## Preview and testing caveats
Advanced checksum/batch/media tools and the independent progress popup still use the established native WPF implementation. Windows scaling, browser-profile permissions and real downloads need device acceptance testing. The EXE is unsigned; SmartScreen may warn. No new cloud sync or telemetry is added. The release pipeline checks the frontend build, .NET unit tests, browser-host smoke, packaging, install/upgrade/uninstall, shortcuts and user-data preservation; these do not guarantee all device-specific behaviours.
